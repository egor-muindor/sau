# sau

Утилита командной строки для публикации переводов на smotret-anime.online
(Anime 365). Одной командой заходит на сайт, заливает видео по частям с докачкой
после обрыва и отправляет форму перевода.

Публикация серии через веб-форму требует ручных шагов, а заливка файла на гигабайт
занимает долго и рвётся при обрыве связи. `sau` делает то же самое из терминала
и переживает обрыв: после перезапуска продолжает с места остановки.

## Установка

Внутри архива один исполняемый файл `sau` (`sau.exe` на Windows). Положите его
в любую папку из `PATH` или просто рядом с видеофайлами и запускайте как `./sau`.

**macOS.** Файл распакуйте, сделайте исполняемым и снимите карантин, иначе система
откажется запускать скачанную из интернета программу:

```
tar -xzf sau_darwin_arm64.tar.gz
chmod +x sau
xattr -d com.apple.quarantine sau
```

**Linux.** Распакуйте и сделайте исполняемым:

```
tar -xzf sau_linux_amd64.tar.gz
chmod +x sau
```

**Windows.** Распакуйте zip и запускайте `sau.exe` из PowerShell или cmd. Если
SmartScreen предупреждает о неизвестном издателе, нажмите «Подробнее» и «Выполнить
в любом случае».

## Первый запуск: вход на сайт

```
sau login --user ВАШ_ЛОГИН
```

Пароль спрашивается в терминале и не показывается при вводе. Сессия сохраняется
и живёт примерно месяц, так что входить снова придётся редко. Проверить, жива ли она:

```
sau login --user ВАШ_ЛОГИН --check
```

Чтобы не вводить пароль при следующих входах, добавьте `--save-password`: пароль
ляжет в системное хранилище (Keychain на macOS, Secret Service на Linux,
Credential Manager на Windows). В конфиг, логи и файлы утилиты пароль не попадает
никогда.

Для запуска без консоли, например по расписанию, пароль берётся из переменной
`SAU_PASSWORD` или из файла, путь к которому указан в `SAU_PASSWORD_FILE`.

## Публикация серии

```
sau upload "Episode 05.mp4" --episode 5 --series 36866 --type voiceRu --authors "Team (Alice & Bob)"
```

Что произойдёт:

1. Утилита проверит сессию и заберёт свежую страницу формы.
2. Предупредит, если у этой серии уже есть перевод с теми же авторами.
3. Разрежет файл на части и зальёт их параллельно, показывая прогресс.
4. Отправит форму и напечатает результат.

Идентификатор сериала виден в адресе страницы тайтла на сайте или в адресе формы
создания перевода: `translations/create?seriesId=36866`. Номер серии указывается
как на сайте: `5`, `12`, для половинных серий `5.5`.

Субтитры заливаются вместе с видео флагом `--sub file.ass`.

### Флаги команды `upload`

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--episode N` | номер серии | обязателен |
| `--series ID` | идентификатор сериала на сайте | обязателен |
| `--type` | тип перевода: `voiceRu`, `subRu`, `voiceEn`, `subEn`, `voiceUk`, `subUk`, `subJa`, `raw` | `voiceRu` |
| `--authors "..."` | строка авторов как она должна выглядеть на сайте | обязателен |
| `--episode-type` | `tv`, `ova`, `ona`, `movie`, `special`, `tv_special`, `preview` | `tv` |
| `--by-author` | отметить, что перевод добавлен его автором | выключен |
| `--channel` | канал раздачи: `cdn`, `all` или `ru` | `cdn` |
| `--sub file` | файл субтитров | нет |
| `--concurrency N` | сколько частей заливать одновременно | `5` |
| `--dry-run` | всё проверить и показать план, ничего не заливать | |
| `--no-submit` | залить файл, но форму не отправлять | |
| `--fresh` | не докачивать, начать заливку заново | |
| `--json` | результат в JSON | |
| `-v` | подробнее рассказывать, что происходит | |
| `--debug` | полный след HTTP в файл для разбора сбоя | |

Перед первой настоящей публикацией полезно прогнать команду с `--dry-run`: она
проверит сессию, файл и параметры и покажет, сколько частей и на какой сервер
пойдёт, ничего не отправляя.

## Файл настроек для онгоинга

Постоянные для тайтла значения удобнее не повторять каждую неделю. Положите в папку
с сериями файл `.sau.toml`:

```toml
user = "ВАШ_ЛОГИН"
series = 36866
type = "voiceRu"
authors = "Team (Alice & Bob)"
episode_type = "tv"
channel = "cdn"
```

Тогда на серию остаётся файл и номер:

```
sau upload "Episode 05.mp4" --episode 5
```

Приоритет источников: флаги, затем переменные окружения `SAU_SERIES`, `SAU_TYPE`,
`SAU_AUTHORS`, `SAU_CHANNEL`, `SAU_USER`, `SAU_CONCURRENCY`, затем `.sau.toml`
в текущей папке, затем пользовательский `config.toml` в папке настроек (см. ниже).

Адреса upload-серверов в конфиг класть нельзя: они меняются, и утилита всегда
берёт их со свежей страницы формы. Такие ключи отвергаются.

## Если что-то пошло не так

**Связь оборвалась или вы нажали Ctrl+C.** Состояние заливки уже на диске.
Повторите ту же команду, и заливка продолжится с места остановки. Список
незавершённых заливок показывает `sau status`.

**Нужно всё отменить.** `sau abort "Episode 05.mp4"` удалит залитый файл с сервера
и сотрёт состояние.

**Сайт отверг форму** (код возврата 4). Утилита печатает причины, которые прислал
сайт. Файл остаётся залитым, после исправления параметров повторите команду:
форму она отправит заново, без повторной заливки.

**Исход отправки неизвестен** (код возврата 6). Так бывает, если связь оборвалась
уже после отправки формы: сайт мог создать перевод, а мог и нет. Повторять
автоматически утилита не будет, потому что это создало бы дубль. Откройте страницу
серии на сайте и посмотрите, появился ли перевод. Учтите, что запись появляется
с задержкой в несколько минут. Затем сообщите утилите ответ:

```
sau resolve "Episode 05.mp4" --submitted    # перевод на сайте есть
sau resolve "Episode 05.mp4" --resend       # перевода нет, отправить форму ещё раз
```

При следующем запуске `upload` для того же файла утилита задаст тот же вопрос сама.

**Сессия протухла** (код возврата 3). Выполните `sau login` ещё раз.

## Остальные команды

```
sau status                         незавершённые заливки
sau series 36866                   справка по тайтлу: список серий с номерами
sau stats [--series ID] [--since DATE]   статистика по журналу публикаций
sau version                        версия сборки
```

Коды возврата: 0 успех, 1 ошибка, 2 неверные аргументы, 3 нет авторизации,
4 сайт отверг форму, 5 заливка не удалась (состояние сохранено), 6 исход отправки
неизвестен, 130 прервано пользователем.

## Где лежат файлы утилиты

| Платформа | Настройки и состояние |
|---|---|
| macOS | `~/Library/Application Support/sau/` |
| Linux | настройки `~/.config/sau/`, состояние `~/.local/state/sau/` |
| Windows | настройки `%APPDATA%\sau\`, состояние `%LOCALAPPDATA%\sau\` |

В папке состояния хранятся сессия сайта, состояние незавершённых заливок, журнал
публикаций `history.jsonl` и, при `--debug`, файл `debug.log`. Пароля там нет.
Переменные `SAU_CONFIG_DIR` и `SAU_STATE_DIR` переопределяют пути.

## Сборка из исходников

Нужен Go 1.27 или новее.

```
go build -o sau ./cmd/sau
```

Тесты работают без сети: `go test -race ./...`. Отдельный контрактный тест против
живого сайта собирается только с тегом `live`, заливает небольшой файл и удаляет
его, форму не отправляет.
